# 培证通 · 培训签到证书平台

主办方创建课程与课次、生成动态签到码；学员扫码签到并完成结业测验，达标后颁发可公开查验的电子证书。
迟到、缺课、补签、补发证书全部有状态、有审批、有审计；旧证书失效后仍可查到**为什么补发**。

## 技术栈

- 后端：Node.js + Express
- 数据库：better-sqlite3（单文件 SQLite，零外部依赖）
- 二维码：`qrcode`（课次签到码、证书查验码）
- 前端：原生 HTML/CSS/JS 单页应用（哈希路由，免构建）

## 快速开始

cd training-cert
npm install        # 如 node_modules 不存在

## 核心业务规则

### 课次与签到窗口

每节课可配置：时长、提前开放分钟数、迟到宽限分钟数、延后关闭分钟数。

- 窗口未开：不能签到；窗口开放后扫码或输入 6 位签到码
- 在 `开课时点 + 迟到宽限` 内签到 → **正常 present**
- 超过宽限、窗口关闭前签到 → **迟到 late**
- 窗口关闭仍无记录 → 系统自动标记 **缺课 absent**（每分钟扫描 + 访问时即时扫描）
- 签到码为一次性活动码，支持一键 **换码**（旧码立即失效）

### 补签状态机

`缺课 absent → 学员提交补签申请（待审核 pending）→ 主办方 批准 / 驳回`

- 批准：考勤改为 **补签 makeup**，与正常签到等价计入出勤
- 驳回：学员可补充材料 **重新申请**
- 每条申请的原因、审核人、审核备注、时间都入库

### 结业条件（双达标）

- 出勤率 =（正常 + 补签 + 迟到×0.5）/ 课次总数 ≥ 课程门槛（默认 80%）
- 结业测验最高分 ≥ 及格线（默认 60 分；可多次作答取最高）

两项同时达标才允许颁发证书，后端强制校验；未达标时会给出具体原因。

### 证书状态与换发链

证书字段：`状态 valid/invalidated`、`类型 initial首发 / reissue补发`、
`supersedes_id`（替换了哪张旧证）、`superseded_by_id`（被哪张新证替换）。

- 发证：单人 / 批量，仅对达标且无有效证的学员成功
- 作废：必须填写**作废原因**，公开查验页永久可见
- 补发/换发：对已失效证书补发；对仍有效证书执行换发时会先按原因自动作废旧证，再发新证
- 任一证书都可沿换发链查到：谁在何时、因为什么原因、把哪张证换成了哪张
- 所有发证 / 作废 / 补发动作写入 `audit_events`，课程页与全局审计页可查

## 页面一览

**主办方**：工作台（统计 + 待审批提醒）、课程管理（课次/签到二维码、花名册与结业资格、
测验编辑、证书样式、证书台账、课程日志）、补签审批、全局操作审计。

**学员**：我的课程（出勤进度条、每节课状态与补签入口、结业资格差距）、
扫码/输入码签到、在线测验（即时判分）、我的证书（换发链 + 打印/查验入口）、课程广场报名。

**公开**：证书查验页（证书纸张渲染、有效/失效印章、换发链时间线、查验二维码）。

## 数据模型

```
users ──< courses ──< sessions ──< signin_codes
   │         │           │
   │         ├──< enrollments >── users(student)
   │         ├──< quizzes ──< questions ──< quiz_attempts
   │         ├──< certificate_templates
   │         └──< certificates ──< certificates   (supersedes / superseded_by 自关联链)
   └──< attendances >── sessions
              └──< makeup_requests
audit_events（跨实体的不可变操作日志） · auth_tokens（登录令牌）
```
